# API-контракт на TypeSpec с генерацией OpenAPI

Публичный API (`docs/spec.md` §6) существовал только в прозе: таблица эндпоинтов и
JSON-примеры в тексте. Такой контракт не проверяется и молча расходится с реализацией —
единственным работающим эндпоинтом долго оставался `/api/health`, а остальные маршруты
жили только на бумаге.

Мы фиксируем контракт в TypeSpec (`spec/*.tsp`) и генерируем из него OpenAPI 3.0
(`spec/output/openapi.yaml`), который коммитится. CI проверяет актуальность
сгенерированного файла (drift-check). TypeSpec — единственный источник истины о контракте;
OpenAPI — артефакт сборки, а не рукописный документ.

Решение трудно откатить: на контракт завяжется не только документация, но и проверки в CI,
а позже — кодогенерация клиентов и валидация. Понадобится переезд моделей и роутов, если
инструмент сменится.

## Considered Options

- **Рукописный `openapi.yaml`** — отвергнуто: два источника истины (спека в прозе и yaml)
  расходятся, нет проверки согласованности, при росте API правки вручную дорожают.
- **Контракт в коде (Zod / JSON Schema рядом с роутами Express)** — отвергнуто: валидация
  покрывает только тела, но не маршруты, статусы и ошибки; контракт смешивается с
  реализацией и не даёт единого публичного описания.
- **Генерация OpenAPI из комментариев/декораторов в Express** — отвергнуто: требует
  аннотаций прямо в коде, связывает контракт с фреймворком и усложняет сервер.
- **TypeSpec (`@typespec/compiler` + `@typespec/http` + `@typespec/openapi3`)** — выбрано:
  проверяемый язык описания API, декораторы валидации (длины, диапазоны, форматы), генерация
  OpenAPI 3.0/3.1, независимость от реализации (бэкенд ещё не написан, контракт готов заранее).

## Consequences

- Единственный источник истины — `spec/*.tsp`; изменения API проходят через правку `.tsp`,
  `npm run spec` и коммит сгенерированного `openapi.yaml`.
- `npm run spec:check` в CI ловит расхождение между TypeSpec и закоммиченным OpenAPI.
- В спецификации один сервер — `http://localhost:3001`; фронтенд ходит на `/api` через
  прокси Vite (см. ADR-0001), поэтому в коде фронтенда абсолютные URL не используются.
- Формат вывода — YAML, OpenAPI 3.0. Эмиттер `@typespec/openapi3` принимает версии
  `3.0.0 / 3.1.0 / 3.2.0`; запрошенная «3.0.3» покрывается веткой `3.0.0`.
